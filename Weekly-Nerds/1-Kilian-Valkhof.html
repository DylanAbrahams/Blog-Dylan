WN 1 - Kilian Valkhof - The Rule of Least Power

Dit is de inhoud voor Weekly Nerd nummer 1 met Kilian Valkhof.

Waar ging het over?

Kilian heeft gesproken over de Rule of Least Power. Dit houdt vooral in dat je vaak moest kiezen voor HTML/CSS aangezien deze stabieler zijn dan JavaScript. JavaScript is krachtig, maar ook complex en breekbaar. Moderne browsers kunnen veel UI-interacties zonder JS. Tijdens de presentatie heeft hij verschillende voorbeelden gegeven van interacties die vroeger altijd met JS werden ontwikkeld waar nu ook HTML/CSS oplossingen voor zijn.

Wat vond ik ervan?

Ik vond dit een interessante presentatie om mee te beginnen. Hij heeft zeker een punt dat een UI-interactie maken met HTML/CSS een stuk consistenter is dan een zelfgemaakte met JavaScript, aangezien een HTML element alles heeft wat nodig is en je met JS alle detail zelf moet regelen. Verder heb je de kans dat JavaScript stuk gaat en je hele interactie stuk kan gaan.

Wel vind ik het een opvallende uitspraak om geen JavaScript te mogen gebruiken ondanks er veel dingen lastig of niet te doen zijn met puur HTML/CSS.

Mijn Aantekeningen

4 februari 2026

Stop using JS for that

JavaScript features overbrengen naar HTML/CSS.

  • Sommige dingen bestaan al een paar maanden, andere al jaren.
  • Al 20 jaar bezig met websites.

Polypane

  • Gratis voor studenten
  • Helpt met responsive design
  • Gemaakt met JavaScript (dus hij is niet tegen JS)

Voor mensen die React gebruiken

  • JSX is een dialect van HTML

Rule of Least Power

  • Choose the least powerful language suitable for a given purpose
  • Als je iets in HTML kan doen, doe het in HTML.
  • Kan het niet in HTML? Gebruik CSS.
  • Pas daarna JavaScript gebruiken.
  • JavaScript is erg breekbaar.
  • Browsers moeten meer moeite doen voor JavaScript dan voor HTML.
  • Oude code blijft vaak jarenlang werken.

Custom Switches

  • Veel developers vragen hierom.
  • Kan met divs en onclick handlers.
  • Kan ook volledig met HTML/CSS via checkboxes.
  • input { appearance: none; }
  • Haalt de standaard styling weg.
  • ::before wordt gebruikt voor de witte stip.
  • ::checked toont de actieve status met CSS.
  • ::focus geeft focus states voor toetsenbordnavigatie.
  • Mensen gebruiken vaak outline: none, maar moeten dan wel een alternatief geven.
  • Safari heeft een speciale input switch modus met eenvoudigere styling.

In-page Transitions

  • Vroeger vaak gedaan met jQuery.
  • Dat was traag voor gebruikers.
  • Kan tegenwoordig met CSS.
  • html { scroll-behavior: smooth; }
  • Sommige mensen worden misselijk van animaties.
  • Gebruik daarom prefers-reduced-motion.

Accordions

  • details verbergt en toont inhoud.
  • summary blijft zichtbaar.
  • p bevat de verborgen inhoud.
  • Met details open staat het standaard open.
  • Het pijltje kan vervangen worden met CSS via ::marker.
  • Gebruik een pointer cursor bij hover.
  • Geef gebruikers feed forward.
  • Op oudere iOS-versies waren interactieve knoppen blauw.
  • Twee details met dezelfde naam kunnen niet tegelijk open staan.

dialog

  • Heeft momenteel nog een beetje JavaScript nodig.
  • Wordt gezien als vervanging voor sommige APIs.
  • Is eigenlijk gewoon een div.
  • Wordt pas zichtbaar wanneer nodig.
  • Animaties hebben een begin- en eindpunt nodig.
  • @starting-style kan gebruikt worden voor animaties.

Al deze punten werken in alle browsers.

Field Sizing

  • Maakt een element automatisch zo groot als de inhoud.
  • Werkt op Chrome en Safari.

Select

  • Select-elementen hebben standaard styling.
  • ::picker(select) { appearance: base-select; }
  • De picker is het dropdown-pijltje van de select.
  • Standaard functionaliteit blijft werken.
  • Onderdelen kunnen individueel gestyled worden.
  • Werkt momenteel in Chrome.
  • Moet expliciet aangezet worden om oude websites niet te breken.

Scroll Driven Animations

  • Animaties gekoppeld aan scrollgedrag.
